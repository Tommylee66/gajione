01

한눈에 보기

핵심 아이디어는 "급여 계산에 CI/CD식 품질 게이트를 씌운 것"입니다. 매월 급여 차수를 G1(근태 무결성) → G2(계산 정합성) → G3(검증·소명) → G4(승인·지급)의 4단계로 강제 통과시키고, 전 단계가 통과해야만 다음 지급 파일이 생성됩니다. 각 게이트는 자동 규칙 검사(예: UMK 미달 여부, 재계산 일치율)와 사람이 판단해야 하는 예외 소명(급여 변동 ±20% 초과자 등)을 분리해서, 자동화가 처리 못하는 부분만 "오늘 결정 큐"라는 받은편지함 형태로 담당자에게 올려주는 구조입니다.

여기에 직원용 모바일 앱(임금 실시간 조회·연차 신청·사내대출)과 페이롤 데이터 기반 신용점수·대출 심사가 같은 데이터 흐름 위에 얹혀 있어, "급여 시스템"이 아니라 근태→계산→검증→지급→직원 신뢰까지 한 바퀴 도는 순환형 HR 핀테크 제품으로 설계되어 있습니다.

눈에 띄는 UX 패턴

결정 큐 (Decision Inbox)

자동화가 못 끝내는 판단만 골라 "오늘 결정 큐"에 담아 담당자에게 제시. 전체 데이터를 훑게 하지 않고 예외만 보여주는 관리 콘솔의 기본기.

회고 루프

"지난 차수 판단은 맞았나?" — 과거 대응(OT 상한 경고, 지문기 오차 보정)이 실제로 재발을 막았는지 다음 차수 홈 화면에서 되짚어줌.

게이트별 진입/이탈 조건 명시

모든 게이트 카드에 통과 조건 체크리스트(N/M)와 통과 시각·담당자·해시가 같이 노출되어 "왜 막혔는지"가 항상 화면에 있음.

확정 전/후 상태 전이

직원 앱의 급여 카운터가 "추정치"(근태 유입 기준) → "확정치"(G2 통과) 배지로 전환. 급여 미확정 리스크를 라벨로 명확히 구분.

순차 전자서명 · 위임 불가

급여담당 → HR장 → 법인장 3단계 서명 체인을 지급 화면에 그대로 노출, 각 서명 시각까지 기록해 내부통제 증빙으로 사용 가능.

페이롤 데이터 → 신용점수 재활용

근태 정확도·상환이력·근속·급여 안정성을 그대로 신용 스코어링 피처로 재사용. 별도 심사 데이터 수집 없이 사내대출/EWA를 지탱.

참고로 함께 첨부된 이미지

스마트팜 운영 대시보드 "Tunas"

zip과 별도로 딸려 온 이 스크린샷은 페이롤 목업과 무관한 스마트팜(온실) 운영 대시보드 "Tunas"이지만, 화면 문법이 거의 동일합니다 — "오늘 결정 큐", "지난 판단은 맞았나?" 회고 루프, 상단 지표 스트립, 우측 이벤트 로그.

같은 "운영 콘솔" 디자인 시스템을 도메인만 바꿔 재사용하고 있다는 뜻으로 보입니다. GajiOne 쪽 목업이 이 패턴을 얼마나 의도적으로 계승했는지 확인해두면, 이후 화면을 늘릴 때 일관성 기준으로 쓰기 좋습니다.
